# 热键绑定系统修复总结

## 🎯 修复目标
解决"Unity 编辑器中正常运行，但打包后热键绑定失效"的问题。

## 🔍 问题根源分析

### 1. InputActionAsset 实例不一致
- **问题**: 编辑器模式下直接使用资产引用，打包后 PlayerInput 创建新的运行时副本
- **后果**: 在设置面板修改的是一个实例，但快捷栏和输入系统使用的是另一个实例
- **修复**: 强制同步所有实例，并在刷新时重新加载

### 2. 缺少强制刷新机制
- **问题**: InputAction 的绑定覆盖需要禁用/启用才能生效
- **后果**: 修改保存后，运行时的 InputAction 仍使用旧绑定
- **修复**: 每次加载后强制 `Disable()` → `Enable()`

### 3. 事件系统可靠性
- **问题**: ScriptableObject 事件在 IL2CPP 打包后可能被优化掉
- **后果**: `onHotkeyChanged.Raise()` 可能不触发 `RefreshHotkeyLabels`
- **修复**: 添加兜底机制，直接查找并刷新所有快捷栏

### 4. 缺少启动加载机制
- **问题**: 游戏启动时没有自动加载保存的绑定
- **后果**: 重新打开游戏后使用默认绑定
- **修复**: 新增 `InputBindingBootstrap` 在启动时自动加载

### 5. 调试困难
- **问题**: 打包后无法知道具体哪一步出错
- **后果**: 难以定位问题
- **修复**: 添加详细的日志系统和诊断工具

## 🔧 核心修复逻辑

### 保存流程
```
用户修改热键
    ↓
ApplySingleBinding() 应用覆盖到 InputAction
    ↓
SaveBindings()
    ↓
KeybindingStorage.SaveOverrides() 保存到 PlayerPrefs
    ↓
InputBindingRuntimeSync.ApplySavedOverridesToAllPlayersFor() 同步到所有 PlayerInput
    ↓
KeybindingStorage.LoadOverrides() 同步到本地引用
    ↓
RefreshQuickBarLabels() 刷新 UI 显示
```

### 加载流程
```
游戏启动
    ↓
InputBindingBootstrap.Awake() 第一次加载
    ↓
InputBindingBootstrap.Start() 延迟加载（确保所有对象初始化）
    ↓
快捷栏 OnEnable()
    ↓
InputBindingRuntimeSync.ApplySavedOverridesToAllPlayersExisting() 再次同步
    ↓
RefreshHotkeyLabels() 刷新显示
```

### 刷新流程
```
RefreshHotkeyLabels() 被调用
    ↓
KeybindingStorage.LoadOverrides() 从本地加载最新数据
    ↓
InputBindingRuntimeSync.ApplySavedOverridesToAllPlayersFor() 同步到 PlayerInput
    ↓
遍历每个槽位:
    - ResolveRuntimeAction() 获取运行时动作实例
    - Disable() → Enable() 强制刷新
    - GetActionDisplayString() 生成显示文本
    - SetHotkeyLabel() 更新 UI
```

## 🎮 使用说明

### 快速开始（3 步）
1. **添加引导脚本**
   - 在主场景创建 GameObject
   - 附加 `InputBindingBootstrap.cs`

2. **启用调试日志**
   - 所有相关脚本的 `DebugLogs = true`

3. **测试打包**
   - 开发构建 → 修改热键 → 重启验证

### 调试步骤（出问题时）
1. **使用诊断工具**
   - 附加 `InputBindingDiagnostics.cs`
   - 运行 Context Menu 中的诊断命令

2. **查看 Player.log**
   - Windows: `%USERPROFILE%\AppData\LocalLow\...\Player.log`
   - 搜索 `[KeybindingStorage]`, `[InputBindingRuntimeSync]`, `[热键]`

3. **检查关键点**
   - PlayerPrefs 是否保存成功
   - PlayerInput 是否找到
   - 绑定覆盖是否应用

## ⚙️ 技术细节

### 为什么需要 Disable/Enable？
```csharp
// InputAction 的绑定覆盖是惰性加载的
// 必须禁用再启用才能强制刷新内部状态
actions.LoadBindingOverridesFromJson(json);
actions.Disable();  // 清除旧状态
actions.Enable();   // 应用新绑定
```

### 为什么需要多实例同步？
```csharp
// Unity 的 InputActionAsset 在运行时会创建副本
// 设置面板：使用 Inspector 中的引用（原始资产）
// PlayerInput：使用运行时克隆的副本
// 快捷栏：可能使用另一个引用
// 所以需要同步所有实例
```

### 为什么需要双重刷新机制？
```csharp
// ScriptableObject 事件在 IL2CPP 打包时可能失效
// 原因：泛型、反射、AOT 编译的限制
// 解决：事件 + 直接查找，确保至少一个生效
```

## 🐛 已知限制

1. **PlayerPrefs 限制**
   - 某些平台可能有大小限制（通常够用）
   - 可能被用户/系统清除
   - 建议：考虑改用 JSON 文件存储

2. **性能考虑**
   - `FindObjectsOfType` 在大场景中较慢
   - 建议：发布版本时缓存引用

3. **平台差异**
   - 移动平台可能有权限问题
   - WebGL 的 PlayerPrefs 行为不同
